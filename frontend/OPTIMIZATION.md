# 闪购集市商城视觉改版记录

## 设计目标

按照用户提供的商城界面设计要求统一顾客商城与运营后台的品牌色与页面基调。保留 Vue 3、TypeScript、Vite、Element Plus 和现有路由/API；不新增未获支持的购物车、结算、分类和订单状态操作，不生成演示商品。

## 本轮改动

| 区域 | 改动 |
|---|---|
| 全站令牌 | 将全局强调色改为品牌红 `#F43F3F`，页面底色改为 `#F5F6F8`，统一正文、次级文字、边线、状态和组件主色变量。 |
| 商城头部 | 白色紧凑导航、红色品牌标识与选中态、白底搜索框；仍只在非目录页展示全局搜索，保留原导航和账号入口。 |
| 首页与秒杀 | 取消蓝紫渐变舞台，改浅红白色活动区域；突出真实活动卡片、真实价格与倒计时。没有活动时使用接口商品/活动计数。 |
| 商品目录 | 桌面四列、大屏五列、平板三列、手机双列；采用统一方图比例、细边框、轻阴影、稳定信息区和红色主要操作。保留筛选、搜索、分页、库存与状态逻辑。 |
| 商品详情 | 使用克制的促销价格区和红色参与按钮；手机上下布局及固定/黏性购买入口沿用既有结构，购买可用性仍由后端活动状态决定。 |
| 登录与注册 | 浅红侧栏/装饰和白色表单卡片，登录注册主按钮统一品牌红，保留原有认证校验与会话流程。 |
| 订单与客服 | 订单终态继续使用语义色；客服面板、消息气泡、快捷问题和发送按钮改用商城品牌红。 |
| 运营后台 | 管理后台仍使用白色工作区和专业表格布局，品牌红只用于品牌标识、当前菜单、主要操作和焦点状态。 |

## 真实业务边界

- 当前前端路由包括商品目录、秒杀专区、商品详情、登录、注册、我的订单和运营管理页面。
- 当前没有购物车、结算、地址、商品分类或售后页面及相应前端接口，本轮未增加这些入口。
- 活动和商品只使用服务端返回数据；当前接口没有活动场次选择栏以外的分类目录数据，不会伪造分类或销量内容。
- 当前后端运行状态：健康检查、商品分页、活动列表和防跨站令牌读取接口可用；匿名读取本人会话返回未认证。活动接口当前返回 18 场 `NOT_STARTED` 活动，未触发抢购、注册、订单创建或其他写操作。

## 修改文件

- `src/styles/main.css`：全局与运营后台品牌颜色令牌、后台选中态/焦点样式。
- `src/styles/storefront-refresh.css`：商城颜色、布局、卡片、表单、详情、订单和响应式改版。
- `src/components/ChatWidget.vue`：客服组件品牌色统一。
- `src/App.vue`：后台标志文字统一为品牌字标。

此前信息精简涉及的页面、认证表单辅助属性和客服自动聚焦也仍保留。

## 验证

`npm run typecheck` 通过，`npm run build` 通过。开发代理下的健康检查、商品分页、商品详情、名称搜索、活动列表、活动详情和防跨站令牌读取均成功；未登录读取本人会话返回业务码 `40100`，符合预期。活动列表当前有 18 场活动且状态均为 `NOT_STARTED`，未执行秒杀提交、注册、订单创建或其他写操作。

工程未配置 `lint`、`test` 脚本，也未安装组件测试或端到端测试框架；本轮未新增依赖。尝试使用本机无头浏览器截图时，浏览器图形进程失败，没有获得可审阅截图，因此实际设备的视觉检查仍需在已启动的 `http://127.0.0.1:5173/` 人工确认。

## 风险与剩余事项

- 构建如继续提示主脚本块超过 500 KB，属于已有依赖/打包体积问题；本轮未调整拆包策略。
- 秒杀写链路未执行，因为当前活动均未开始；测试不会伪造可成功下单的状态。
- 登录/注册写流程需要专用测试账号与数据清理策略；本轮不创建持久测试账号。
- 需要在实际浏览器中复核桌面、平板、手机视觉和辅助操作；构建、类型与接口读取检查不能替代人工视觉验收。

- 将登录/注册、商城搜索、客服发送、客服浮动入口和用户消息气泡的实色背景调整为深品牌红 `#C32929`，悬停使用 `#A91F1F`，让白色文字与按钮背景保持清晰对比；促销价格和装饰强调仍使用亮红。
