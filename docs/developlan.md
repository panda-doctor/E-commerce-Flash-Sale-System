### 第1周：基础设施与基础缓存（5天）
**目标**：项目跑通，深刻理解缓存设计模式与三大问题解决方案。

| 天       | 任务详解                                                     | 产出/验证方式                        |
| -------- | ------------------------------------------------------------ | ------------------------------------ |
| **Day1** | 1. Docker 一键部署 Redis 7 + MySQL 8<br>2. 初始化 Spring Boot 工程，集成 MyBatis-Plus、Redisson<br>3. 建表：商品表、秒杀活动表、订单表 | 测试接口可连上 MySQL 和 Redis        |
| **Day2** | 1. 实现商品信息查询接口 `/product/{id}`<br>2. 实现**缓存旁路模式**：先查 Redis，未命中查 DB 并回写<br>3. 主动设置随机过期时间（如 30+随机秒）防雪崩 | Postman 验证缓存命中与过期逻辑       |
| **Day3** | 1. 解决**缓存穿透**：对不存在商品 id 在 Redis 存空值，设置短过期<br>2. 解决**热点 key 击穿**：使用 Redisson 分布式锁实现"互斥更新" | 用日志验证大量并发请求只有一个查库   |
| **Day4** | 1. 管理端：预加载秒杀商品到 Redis（库存预热）<br>2. 设计一个简单的秒杀活动时间窗口，存入 Redis Hash 用于快速校验 | 访问 `/seckill/check` 能返回活动状态 |
| **Day5** | 复习与单元测试：使用 `RedisTemplate` 操作各种数据结构，为下周准备 | 跑通 Redis 五种基本数据结构练习      |

---

### 第2周：秒杀核心——原子库存扣减（5天）
**目标**：实现真正的高并发秒杀逻辑，杜绝超卖，掌握 Lua 原子操作。

| 天       | 任务详解                                                     | 关键 Redis 技术                    |
| -------- | ------------------------------------------------------------ | ---------------------------------- |
| **Day1** | 编写库存扣减 Lua 脚本：<br>`if stock>0 then decr; return 1; else return 0; end`<br>配置 `RedisScript` Bean | Lua 脚本保证原子性                 |
| **Day2** | 开发秒杀核心接口 `/seckill/execute`：<br>1. 校验活动时间 (从 Redis 读)<br>2. 执行 Lua 扣减库存<br>3. 返回"排队中"或"已抢完" | 库存 key：`seckill:stock:1`        |
| **Day3** | 引入 JMeter：录制或编写并发测试脚本（1000 并发/秒抢 100 个库存），验证库存始终不为负 | 观察 Redis 中库存值是否精确到 0    |
| **Day4** | 实现用户维度"已购"防重：首次用 `SETNX` 创建用户购买凭证令牌（如 `seckill:uid:1:goods:1`），30分钟过期 | 同一用户反复请求返回"请勿重复秒杀" |
| **Day5** | 将 Lua 脚本与令牌检查合并：库存扣减前先 `exists` 令牌，整合在同一个 Lua 中保证原子性 | 合并后更高并发下依旧无超卖         |

---

### 第3周：高并发防护体系（6天）
**目标**：构建企业级的流控、防刷、异步削峰能力，理解分布式协调。

| 天       | 任务详解                                                     | 关键技术                           |
| -------- | ------------------------------------------------------------ | ---------------------------------- |
| **Day1** | **分布式锁防一人多抢**：用 Redisson 的 `RLock` 对 `userId+goodsId` 加锁，包围"查令牌+扣库存"逻辑 | Redisson 自动续期、可重入          |
| **Day2** | **接口级滑动窗口限流**：编写 Lua 实现 ZSet 滑动窗口，单用户 1 分钟内只允许 5 次秒杀请求，网关或拦截器应用 | key: `rate:limit:{userId}`         |
| **Day3** | 将限流逻辑加在 `/seckill/execute` 之前，并在超限时返回 429 状态码 | JMeter 压测限流效果                |
| **Day4** | **引入 Redis Stream 削峰**：秒杀请求检验通过后，不直接落库，而是发布消息到 Stream `seckill:order:stream` | 消息体：userId,goodsId,timestamp   |
| **Day5** | **实现消费者**：`@Scheduled` 或新线程读取 Stream，消费消息生成订单并写入 MySQL，使用消费者组保证消息不丢 | 模拟消费者宕机后重启，消息仍可消费 |
| **Day6** | 完善消费者异常重试、死信处理（消费失败超过3次移入另一个 Stream 人工处理） | 日志观察消费顺序与最终一致性       |

---

### 第4周：排行榜、前端与全链路压测（5天）
**目标**：形成完整产品雏形，并通过压力测试复盘所有 Redis 方案的性能表现。

| 天       | 任务详解                                                     | 成果                        |
| -------- | ------------------------------------------------------------ | --------------------------- |
| **Day1** | **实时秒杀成功榜**：消费者成功生成订单后，执行 `ZINCRBY seckill:rank 1 userId`，用 `ZREVERANGE` 返回 Top10 | 接口 `/rank/top10`          |
| **Day2** | 简单前端页面（Thymeleaf + Vue.js 可选）：显示商品信息、秒杀按钮、库存倒计时、实时排行榜 | 页面可点击并接收结果        |
| **Day3** | 前后端联调，处理按钮状态（未开始、进行中、已抢光、重复抢），优化体验 | 完成一个可演示的闭环        |
| **Day4** | **全链路 JMeter 压测**：构造 5000 并发请求，验证以下指标：<br>- 库存精确性<br>- 限流拒绝数<br>- 订单生成延迟<br>- Redis CPU/内存 | 输出压测报告与截图          |
| **Day5** | 代码复盘、补充异常处理，整理学习笔记，列出每种企业问题对应的 Redis 解决方案与代码位置 | 一篇自己的《Redis实战总结》 |
